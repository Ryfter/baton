This is the release where the golden path stopped being a design and started being a path. The

## What shipped

### Engine expressiveness — the gates were ahead of the engine (#115 slice 1, #128 slices 2–3)

The bakeoff's #128 was a Catch-22: the plan gate demanded a remediation task, but the engine had
no conditional tasks and no way to pass one task's output to another, so every plan that satisfied
the gate was unbuildable. Three slices closed it:

- **Task-output bus** (#115 slice 1, PR #130) — a worker's output is captured and injected into
  dependent tasks as **advisory data, never authority**. Verification contracts still freeze from
  the base revision, so a wrong or poisoned upstream output can waste a task but cannot widen
  `allowed_paths` or weaken the oracle. Held under adversarial probing.
- **Engine-owned rework loop** (#128 slice 2, PR #132) — the existing one-evidence retry is
  subsumed into a single rework loop with one counter and one vocabulary, a hard ceiling
  (default 1), and evidence-only synthesis. Scope and oracle violations stay fail-closed with
  no retry.
- **Rework contract in the gate briefing** (#128 slice 3, PR #133) — the plan-gate reviewer is
  told what the engine will do automatically after review, so it stops demanding always-on
  remediation tasks the engine now handles itself. Includes a bias guard against
  over-generalizing the overbuild guidance.

**Acceptance (d095):** three runs on the *unmodified* S1-A brief with **zero in-DAG-remediation
demands**. The plan gate passed that brief for the first time (previous score: 0/3).

### The bakeoff defect chain — four legibility/correctness fixes

- **#136 → PR #137** — the worker prompt now carries the task's `allowed_paths`. The scope oracle
  was rejecting honest work because the sandbox it enforced was one the worker had never been
  shown. The oracle stays the authority; the worker just gets to see the rules.
- **#134 → PR #138** — the acceptance-rework scope check **fails closed when it cannot check**.
  Previously a null tree snapshot silently skipped the check and re-panelled unverified labor.
  Both the pre- and post-rework snapshot failures now halt with `reason: scope-uncheckable`.
- **#135 → PR #139** — a dispatch failure journals the spawner's actual diagnostic instead of
  echoing the task description the operator already had.
- **#124 → PR #141** — an empty labor pool no longer masquerades as `verification-failed
  (no-change)`. A per-provider audit splits **config-shaped** exclusions (disabled, no capability
  claim, not edit-eligible, context floor, tier cap) from **availability** exclusions (lockout with
  `reset_at`, cooldown, conserve-mode limited), and an availability-emptied pool halts as
  **`labor-unavailable`** with a `worker-selection-failed` event and a `## Labor` report section
  naming each provider and its reset. Config-shaped pools keep the #127 stakes/tier remedy;
  mixed pools get both (d097).
- **#127 → PR #129** (shipped 2026-07-23) — planner capability tier-floor evidence and the
  zero-candidate remedy message.

### First-run onboarding (#118, PR #142)

A target repo without a **committed** `.baton/verification.json` could never pass default
`--execute` — no oracle can freeze, so every plan was rejected. Correct, but a dead end. Now
`--execute` detects it **before the worktree exists and before any dispatch** and prints the cause,
the detected toolchain, and the exact remedy. `--scaffold-verification` writes schema-1 preset
sugar and **stops** — it never commits for you, because the artifact that judges the labor should
not be committed by the thing being judged, and an uncommitted config cannot freeze anyway (d098).

Four states, each with its own remedy: `ready`, `uncommitted`, `empty`, `missing`. A repo with no
recognizable toolchain gets the schema and preset list rather than a silently-installed weak oracle.
`docs/COMMANDS.md` gains the first-run section that never existed — the undocumented half of #118.

### Conductor cost honesty (#114, PR #140)

Ship-report cards aggregated instrument spend only; the conductor's own tokens rendered as a
hardcoded `not tracked`. The card now meters conductor spend from the Claude Code session
transcripts the harness already writes (exact API usage, deduped by message id, subagent turns
included, windowed to the card's dispatch→merge span), rendered with an explicit upper-bound
caveat — or an honest `not metered` line when there's no telemetry. It is **never summed into the
instrument totals**: different meter, different money (d059, d096).
